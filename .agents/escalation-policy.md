# Escalation Policy

Escalate to the Architecture Agent when:

- an API or YAML contract must change;
- a runtime boundary or Spark/Databricks behavior must change;
- a new structural dependency is proposed;
- the chosen technical pattern no longer fits;
- blast radius is higher than expected;
- implementation requires significant refactoring;
- review finds architecture drift.

Escalate to the human user when:

- product behavior is ambiguous;
- roadmap priority changes;
- a timeline versus quality trade-off is needed;
- known debt must be explicitly accepted;
- security or compliance risk is unclear;
- the task cannot be completed within agreed scope.
